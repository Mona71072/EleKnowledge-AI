# 配布資料の共通デザイン基準

## 目的・適用範囲

マニュアル、操作手順、議事録、FAQ、一覧、案内文等、利用者・キーマンへ配布する文書の共通デザインを定めます。今後の新規作成・改訂時に適用し、PDF・Word・HTML等の形式が変わっても、同じ資料群として読める体裁に揃えます。

利用者が別の書式や既存テンプレートを明示した場合は、その指定を優先します。会議用の図や画面画像は内容に適した表現を保ち、文書側の見出し・余白・書体を揃えます。

配布資料の作成・改訂時に本書を参照するルールは [AGENTS.md](../AGENTS.md) が正本です。書式の数値、確認方法、採用理由の正本は本書とし、各AIツールの指示ファイルには転記しません。

## 基準とする資料・採用理由

次の採用済み資料を共通の見本とします。

- [法令RAG 取扱法令一覧（2026年10月15日版）](user-manual/legal-rag/法令RAG_取扱法令一覧_2026-10-15.pdf)
- [利用者向けFAQ（2026年10月20日版）](user-manual/Ele-Knowledge_FAQ_20261020.pdf)
- [キーマン打合せ議事録（2026年10月15日）](key-persons/Ele-Knowledge_キーマン打合せ_議事録_20261015.pdf)

2026年10月20日の利用者確認で、法令一覧にFAQ・議事録のデザインを揃える方針が採用されました。資料ごとに体裁を作り直す手戻りを減らし、文書種別が違っても見出しや根拠を追いやすくするため、以後の配布資料にも同じ基準を使用します。

法令一覧の [生成スクリプト](user-manual/legal-rag/build_pdf.py) を数値の照合元としています。このスクリプトは法令一覧専用であり、別資料の生成時に取り込み処理ごと実行するものではありません。

## 用紙・書体・文字サイズ

| 項目 | 基準 |
| --- | --- |
| 用紙 | A4縦 |
| 余白 | 上・左・右16mm、下18mm |
| 書体 | BIZ UDPゴシック。通常・太字を使い分ける |
| 大見出し・タイトル | 18pt、行送り26pt、太字 |
| 節見出し | 13.5pt、行送り23pt、太字 |
| 小見出し・質問見出し | 11.5pt、行送り19.55pt、太字 |
| 本文 | 10.5pt、行送り17.85pt（約1.7倍） |
| 表内 | 9.8pt、行送り16.66pt。表見出しは太字 |
| 補足・注記 | 9pt、行送り15.3pt |
| ヘッダー・フッター | 6pt |

PDF生成時には日本語フォントを埋め込み、別端末でも文字化けしないことを確認します。BIZ UDPゴシックを使用できない環境では、游ゴシック等の日本語ゴシック体で可読性・改行を確認し、使用書体を作成記録に残します。ページ数を減らすために本文を小さくしません。

## 配色・見出し・表

| 要素 | 基準 |
| --- | --- |
| 本文・主要見出し | `#1A1A1A` |
| 補足・説明 | `#475569` |
| ヘッダー・フッター | `#64748B` |
| 大見出し左罫線 | 青 `#1D4ED8`、4.5pt |
| 大見出し背景 | 淡い青 `#EFF6FF` |
| 見出し下線 | 淡い青 `#93C5FD`、1.5pt |
| 小見出しの強調色 | 濃い青 `#1E3A8A` |
| 表見出し背景 | 淡い青 `#EFF6FF` |
| 表の格子罫線 | グレー `#CBD5E1`、0.75pt |

大見出しは淡い青の帯と青い左罫線で示します。帯内の余白は左4mm・右2mm・上下2mm、帯の後は6mmを目安に空けます。節見出しやFAQの質問見出しには淡い青の下線を使用し、本文と区別します。

表の内容は上揃え、セル内余白は左右2.5mm・上下1.5mmを基本とします。長い項目は列幅を調整して折り返し、表が複数ページにまたがる場合は見出し行を繰り返します。行の途中で分割しないようにします。

配色・書体は統一しますが、本文をすべて表にする、一定のページ数に収める等の構成は強制しません。資料の長さと内容に合わせて表・段落・改ページを選びます。

## ヘッダー・ページ番号・版情報

- 上部左に文書名、上部右に版・日付等を置きます。A4では左右端から16mm、上端から約7mmを目安にします。
- 下部中央に「ページ / 総ページ数」を置きます。下端から約5mmを目安にします。
- 日付の意味を区別します。議事録は開催日、一覧は一覧基準日・資料作成日、マニュアルは改訂履歴に記録する日付として扱います。書式統一だけを理由に内容の検証日や開催日を進めません。
- 表紙や版情報の掲載方法は、その文書で定めた運用を維持します。例えば利用者マニュアルの表紙に版・作成日を追加せず、[既存の版管理方法](user-manual/README.md)に従います。

## 作成・改訂時の確認

1. 作成前に本書と見本を読み、編集用正本・配布形式・配布先を確認します。本文内容の決定と書式変更を区別します。
2. PDF・Word・HTML等、作成する各形式へ共通書式を適用します。Wordで同じ行送りを再現する場合も、表や長文の折り返しは出力結果で確認します。
3. 体裁だけを変更する場合は、変更前後の本文・表の文言と順序を照合します。本文の修正を伴う場合は、変更箇所を分けて記録します。
4. 配布用PDFは全ページを表示し、文字化け、文字切れ、表のはみ出し、見出しだけがページ末尾に残る状態、ページ番号を確認します。抽出テキストでも記載漏れがないことを照合します。
5. 編集版と配布版の質問・回答・表の内容が一致し、参照リンクと案内が配布先の閲覧権限に合っていることを確認します。キーマン限定のTeamsへ一般利用者が直接アクセスできる前提にしません。
6. 採用版を所定の場所へ保管し、索引のリンクを更新します。書式の確認と、本文の仕様・実機確認は別に記録します。

## 保管先と過去資料

| 資料 | 保管先 |
| --- | --- |
| 現行の利用者向けマニュアル・FAQ等 | [docs/user-manual/](user-manual/README.md) |
| キーマン向け議事録・Forms原稿等 | [docs/key-persons/](key-persons/README.md) |
| 会議向けに準備した説明・検討資料 | [docs/meetings/YYYY-MM-DD/](meetings/README.md) |

過去の会議準備資料や検証記録を本基準の追加だけで一括改稿・再生成しません。依頼された文書の改訂時に適用し、当時の内容・日付を保持します。議事録等の正本は一か所に置き、会議フォルダーからはリンクで案内します。

## 基準を変更するとき

変更する書式と影響する文書種別を本書で明示し、共通基準の変更として確認します。数値・採用理由を別のREADMEやAIルールへ複製せず、各入口は本書へのリンクを維持します。

2026年10月20日に、見本3資料と法令一覧生成スクリプトの書体・サイズ・配色・余白・表・ヘッダー・ページ番号、および本文書の参照先を照合しました。既存マニュアル全体の再検証・再生成は行っていません。
