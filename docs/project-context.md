# Ele-Knowledge プロジェクト背景

> **状態:** ドラフト。資料とitai共有情報に基づく背景整理で、部門横断の確認前。

## この文書の目的と範囲

**目的:** Ele-Knowledgeの検討が始まった事業・組織上の背景と、背景情報の出典・確度を記録する。

**扱う情報:** 施策の発端、関係する組織・取り組み、背景として共有された情報とその確認状態。

**扱わない情報:** 個別利用者の職務・課題は[利用者と業務課題](./user-needs.md)、製品が実現する価値は[製品意図](./PRODUCT_INTENT.md)、将来の製品案・日程は[製品ロードマップ](./product-roadmap.md)、開発運用は[ops-ai-driven-dev.md](./ops-ai-driven-dev.md)を参照する。

**文書群の案内:** [README.md](./README.md)

## 施策の背景

ユーザー共有の概要資料では、社内資料が複数システムに分散していること、必要情報への到達に時間がかかること、経験や知識が担当者に依存しやすいことを課題として挙げ、検索時間の短縮と根拠に基づく判断の支援を目的としている。

これは資料に記載された問題認識であり、部門横断の調査で確認済みの実態を意味しない。各部門の状況や優先課題は[利用者と業務課題](./user-needs.md)に記載した仮説を起点に、関係者へ確認する。

## 組織上の前提

- 工事部門は、昇降機新設工事部（昇新工）、昇降機モダニゼーション工事部（昇モ工）、空調冷熱・システム工事部（空シ工）に分かれる。昇新工は昇降機の新設・据付、昇モ工は昇降機の改修、空シ工は空調冷熱・計測設備・ビルシステム工事を担当する。
- 現場代理人と品質管理担当者が各部門の業務を担当する。昇新工と昇モ工では品質管理担当者の一本化が進んでいる。
- 空シ工には別部門のAIプロジェクトがある可能性が共有されているが、2026-10-02時点で未確認。Ele-Knowledgeの対象とするかは、重複開発を避ける観点も含めて関係部門と協議する。
- itai・monaは昇降機の品質管理担当者であり、空シ工の業務には詳しくない。この立場による知識の偏りを、部門全体の合意と混同しない。

## 資料の読み分け・未決事項

| 論点 | 出典と現時点の扱い | 次の確認・判断 |
|---|---|---|
| 対象部門 | 概要資料は工事部門への展開を示す一方、現行の主対象は昇降機工事。空シ工は将来候補であり、対象化は決定していない | キーマン・開発部門からニーズと別AIプロジェクトの状況を確認し、itai・monaが対象範囲を判断 |
| マルチエージェント | 概要資料の専門家チーム図と段階構想は将来案。現行の通常／じっくり2モードは単一AIの固定ワークフローであり、現在の仕様との矛盾として扱わない | 将来案の採否は各専門領域のニーズ・効果・費用・共通基盤を確認してからitai・monaが判断。詳細は[2モード決定記録](./decisions-2026-09-24-rag-two-modes.md) |
| 利用者の課題 | 資料分散・暗黙知・若年層の検索負荷はitai個人の経験に基づく仮説で、全部門の共通事実ではない | 各部門のキーマン・利用者に確認し、根拠と適用範囲を記録 |
| 全国展開 | 元資料の展開・効果は計画や試算。開発側だけで全国展開を決めない | 試行の実測結果を判断者へ提示する。評価方法の具体化は別Issueで扱う |
