**範囲:** 既存のdevelop / AWS dev環境の反映確認、利用者マニュアル、受入確認、費用・利用状況の計測。対象範囲と費用条件の正本は[対象法令一覧 §2.3](features/development/legal-rag-target-laws.md#23-決定記録dev利用範囲共同確認の状態)、技術仕様は[法令RAG設計](features/development/legal-rag-design.md)と[法令API補足](api/legal-chat.md)。本書で対象拡大や新たな支出を承認しない。

### 2026-10-09 公開反映の修正方針

> 最終検証: 2026-10-09 — Amplify job 63、develop `795aa0a2`、RAG Lambdaの必要設定を読み戻した。

#170で法令公開フラグを追加したdevelop `795aa0a2`のビルドは、`@tailwindcss/postcss`を読み込めず失敗していた。Node 22の選択は成功しており、`NODE_ENV=production`下の`npm install`がビルドに必要なdevDependenciesを省略したことと整合する。

修正はAmplifyの**developブランチのみ**に`NPM_CONFIG_INCLUDE=dev`と`NEXT_PUBLIC_LAW_RAG_ENABLED=true`を設定し、既存のブランチ環境変数を保持して再ビルドする。採用コミットはマージ済み`795aa0a2`。ビルド用依存をインストールしても`NODE_ENV=production`での生成は維持する。Lambda・KB・本番ブランチの変更は含めない。ビルド成功後に、実配信ホームのカードから法令画面へ開けることを確認する。

実施結果: job 64のBUILD / DEPLOY / VERIFYはすべて`SUCCEED`。developの法令カード・プレリリース表示・カードからの法令画面への遷移を実確認済み。この2画面はマニュアルへ反映した。新しい質問による回答生成は今回のカード公開確認には含めていない。

根拠: npmの[include / omit設定](https://docs.npmjs.com/cli/v11/using-npm/config#include)では、`NODE_ENV=production`時の既定はdev依存省略だが、`include=dev`を指定するとインストール対象に戻せる。

## 3. dev反映の手順

1. 既存devのコード・パラメータを読み戻し、採用するdevelopコミットと比較する。他テーマの先行反映がある場合、developの単体デプロイで巻き戻さず差分を整理する。
2. Lambda / SAMの反映が必要ならitaiが統合済みソースからbuild/packageし、変更セットを確認する。通常KB、生成モデル、S3/KMS、IP制限、スロットリング等の既存値を保持する。意図しない置換・削除・通常検索の設定変更があれば実行を止める。
3. Amplifyの法令公開フラグをdevelopブランチ単位で明示設定し、再ビルド・配信結果を確認する。mainや共通ビルド設定を一括でONにしない。
4. itai配信版の実アカウント操作はユーザー確認済み。develop反映後は、法令カードから開けること、回答・原文・履歴の主要動線と画像の一致を確認する。§4は確認結果の記録用に使い、申告されていない個別試験まで合格扱いにしない。
5. [管理者向け確認表](user-manual/admin-verification-sheet.md)と[確認記録](verification-2026-10-09-legal-chat-prerelease.md)へ結果を記入し、利用者マニュアルの表記・画像・PDFと配信版を照合する。

今回の試行反映に追加の法令取得・KB Syncは含めない。取込ツールの操作は[実装README](../scripts/legal_rag/README.md)にあるが、存在するコマンドを追加同期の許可とは扱わない。

## 5. 試行中の計測と停止

利用対象はdev環境の全ユーザー。実費は今後確認し、人数の集計や実費の確定を試行開始前の追加条件にはしない。

月額仮上限、責任者、評価期限は対象一覧の決定記録を参照する。実利用者数、代表質問の解決状況、原文到達、応答時間、入力／出力token数、実費、更新・監視・問い合わせ対応の工数を、期間と取得方法付きで記録する。本文文字数をtoken数や実請求額へ読み替えない。現行ログで法令別に費用を分離できない場合は、その限界を明記する。

利用停止が必要ならitaiがフロントのカード表示とバックエンドの法令ゲートを停止対象として確認する。フロントだけを非表示にしてAPI停止済みとしない。変更セットは法令IAM条件にも連動するため、既存通常RAGへの影響を確認する。停止はデータ削除と分け、KB / DataSource / S3の削除・追加同期・対象拡大は今回の許可範囲に含めない。
