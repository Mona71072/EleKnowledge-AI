# KB 修正依頼の台帳（共有 KB `VQV81CNYU4`）

> **目的:** RAG が使う Knowledge Base は別部門のスタック（`RagKnowledgeBaseStackINSTD`、GenU 由来の共有 KB）が所有し、本システムは読み取り専用で使っている（[decisions-2026-08-26-kb-selection.md](./decisions-2026-08-26-kb-selection.md)）。精度を上げるために **KB 側で直してほしい点** をここに集め、itai と所有部門へ随時共有する。
>
> **正本:** KB 側への依頼事項はこの台帳だけに書く。決定の経緯は [decisions-2026-09-24-rag-two-modes.md](./decisions-2026-09-24-rag-two-modes.md) の D4。
>
> **更新のしかた:** 新しい問題が見つかったら行を足す。所有部門に伝えたら「状態」と「連絡日」を更新する。対応済みになったら、実測で確認してから「完了」にする（行は消さない）。
>
> **確度:** 「確認済み」は主に 2026-08-26 の AWS / S3 実測時点での確認（frontmatter の last-verified もこの日）。現在の状態は再実査していない。台帳としての取りまとめは 2026-09-24。

## 優先度の案

1. **KB-01 索引漏れ** — アプリでは救えない。Q シートは約 8% が検索不能。
2. **KB-02 Sync の運用** — 資料を直しても、再 Sync されなければ利用者に届かない。
3. **KB-12 表・図の解析** — 基準値の取り違えという、記録された誤答の種類に直結する。
4. **KB-05 用途外データソースの混入** — 関連性と引用の開けなさに影響する。
5. **KB-03 / KB-04 機種メタデータの型** — 今はアプリが吸収しているが、AWS 仕様の保証外の挙動に頼っている。

次点は KB-07（機種コードの正規化）と KB-08（説明の付与。まず現行データで再集計）。
