# 利用者マニュアルの原稿・配布物

**目的:** 更新する原稿と配布候補を区別し、管理者が確認・再生成できる入口。

## 現行の更新対象

- 原稿: [利用者マニュアルHTML](eleknowledge-user-manual.html)。第2版は法令チャットの説明を追加した版。確認用途を示すラベルは利用者向け文書に記載しない。
- 版管理: 表紙にはバージョン・作成日を記載せず、末尾の「改訂履歴」でバージョン・改訂内容・改定日を表にまとめる。第1版の作成（2026-09-09）、同版の訂正（2026-09-11）、第2版（2026-10-09）を記録する。
- 利用者向けの記載: 表紙の対象者は第1版と同じ「東日本支社 工事統括部　現場代理人・品質管理担当者」。利用者による提供範囲の区別は記載しない。itaiブランチはdevelop反映前の開発確認用で、利用者への展開先ではないため本文に記載しない。撮影元は本READMEと確認記録で管理する。
- 目次: HTML・PDFともに各章・付録A／B・改訂履歴の項目から該当箇所へ移動できることを確認する。
- 確認表: [管理者向け確認表](admin-verification-sheet.md)。第1版の確認記録を保持し、第2版の残作業を冒頭で管理する。
- 配布候補: `EleKnowledge_利用者マニュアル_v2.pdf` / `EleKnowledge_管理者向け確認表_v2.pdf`。PDFの生成・組版確認を、配信版の通し操作確認とは区別する。
- 第1版PDF: `*_v1.pdf`は2026年9月時点の旧配布物として保持する。法令チャットの案内には第2版を確認して使用する。
- 画像: `images/`。通常チャットの既存画像は過去の例。`23-law-*`〜`28-law-*`はitai配信版の実撮影6枚、`29-law-*` / `30-law-*`は公開反映後のdevelop実撮影2枚（いずれも2026-10-09）。原稿のホーム・初期画面はdevelop画像を使用する。認証・API応答を差し替えず、個人情報が写らない範囲を掲載した。

## 再生成

リポジトリルートから、既存のMarkdown / Playwright / Chromiumを使う。プロジェクトのアプリ依存へ生成専用パッケージを追加しない。

```powershell
python docs/user-manual/build-admin-html.py
node docs/user-manual/build-pdf.js
```

Playwrightを別の作業用ディレクトリに用意している場合は、既存スクリプトの`PLAYWRIGHT_DIR`でそのディレクトリを指定できる。生成される`admin-verification-sheet.html`は中間成果物であり、正本はMarkdown。

2026-10-09の配布候補は、既存Python環境のMarkdownで管理者HTMLを生成し、インストール済みEdgeのheadless印刷で両HTMLをPDF化した。Playwrightによる再生成は今回実行していない。Edgeを使う場合も専用の一時プロファイルを使用し、HTML内の用紙サイズを反映する。管理者PDFの文書リンクはGitHubのdevelop上のパスに変換し、作成端末のローカルパスを含めない。新規文書のリンク先は文書PR反映後に利用できる。

利用者PDFの目次14項目（1〜11章、付録A／B、改訂履歴）はPDF内部の名前付きリンクとして生成され、該当する見出しのページを指すことを検証済み。HTMLのリンク先IDの存在・重複なし、PDFの対象者表記、削除した表現が本文に残っていないこと、ローカルファイルURLを含まないことも確認した。利用者PDFは38ページで、最終ページに改訂履歴の表を掲載。表紙・目次・改訂履歴の組版を確認した。
