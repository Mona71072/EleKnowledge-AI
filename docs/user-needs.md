# Ele-Knowledge 利用者と業務課題

> **状態:** ドラフト。itaiの一担当者としての認識が中心で、各部門の利用者確認・実測前。

## この文書の目的と範囲

**目的:** 製品検討の根拠となる利用者の役割・業務・課題認識を、確認済みの事実と仮説を区別して記録する。

**扱う情報:** 利用者区分、担当業務、情報探索・知識共有上の課題、確認が必要な利用者仮説。

**扱わない情報:** 組織・施策の背景は[プロジェクト背景](./project-context.md)、製品として提供する価値は[製品意図](./PRODUCT_INTENT.md)、解決案や展開時期は[製品ロードマップ](./product-roadmap.md)を参照する。

**親・関連文書:** [プロジェクト背景](./project-context.md) ／ [文書群の案内](./README.md)

## 利用者区分と業務

| 利用者 | 担当業務の認識 | 確認状態 |
|---|---|---|
| 現場代理人 | 昇降機、空調冷熱・計測設備、ビルシステム工事の現場代理人業務 | itai共有。各部門の確認前 |
| 品質管理担当者 | 同じ工事領域における品質管理業務 | itai共有。各部門の確認前 |

対象部門の構成・担当領域は[プロジェクト背景](./project-context.md#組織上の前提)を参照。itai・mona自身は昇降機の品質管理担当者で、空シ工の業務知識は限定的。

## 課題認識（仮説）

以下は昇降機の品質管理担当であるitaiの経験に基づく認識であり、全利用者・全部門で確認された事実ではない。

- 資料化された情報が多くある一方、資料化されていないノウハウがベテラン担当者に集中し、口伝や現場で継承されているため、他者が参照できる文書・メモになっていない場合がある。
- 資料管理部門ごとに閲覧システムが異なり、情報を探す際は、まず資料カテゴリと閲覧システムを特定する必要がある。
- 特に若年層では、必要情報へ到達するまで時間がかかり、検索・確認自体が負担になっていると感じている。
- そのため、工事部門の資料・法令・ノウハウを、資料カテゴリや管理部門を意識せず口語で横断検索できる仕組みは有用ではないか、という仮説がある。

## 確認が必要なこと

- 各部門の現場代理人・品質管理担当者が、どの情報探索・知識継承業務にどれほど時間を使っているか。
- ノウハウのうち何が未文書化で、誰が内容を確認・承認できるか。
- 空シ工の利用者ニーズと、既存・開発中AIプロジェクトとの役割分担。
- 若年層を含む利用者区分ごとの課題・利用環境の差。
