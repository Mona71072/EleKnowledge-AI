# 決定記録: 共有 KB の資料 2 件の移管・復元と機種追加（2026-11-13）

> **状態:** 実施済み（2026-11-13、itai の判断で実施）。**mona の確認待ち**（業務スコープ変更の事後確認。AGENTS.md「業務スコープ変更の共同確認」）

> **コード・IaC の変更:** なし。S3 のオブジェクトと KB の取り込み（Sync）だけを変えた

## 1. きっかけ

develop 環境のチャットで、引用リンク `IN-EL-12-107-01.pdf` が開けなかった（2026-11-13 13:19 JST、`GET /rag/document` が 400）。

- この資料は KB バケットではなく、quick-start データソース `A0XLFVSX3P` の fmp バケット（`s3://rag-data-source-inst-fmp-<DEV_ACCOUNT_ID>-ap-northeast-1/docs/`）にだけ置かれていた
- 引用の中継 API は、`KB_SOURCE_BUCKET`（`docs/` 配下）と `DOCUMENTS_BUCKET` 以外を `InvalidDocumentUri` の 400 で拒否する（`app.py` の `is_allowed_document_uri`）。fmp バケットは対象外のため、検索・引用はされても開けなかった
- 2026-09-04 に fmp 側へ metadata（カテゴリ「据付ノート」）が付いたため、カテゴリの許可リスト（`ALLOWED_CATEGORY_VALUES`）も通っていた
- chatlogs-dev では、引用のある回答のうち 9 月 4/22・10 月 13/146・11 月 13/70 件にこの資料が含まれていた。`/rag/document` の 400 は 9/29 に 1 件、10/6 に 2 件、11/13 に 1 件
- 最近の開発による変化ではない（`A0XLFVSX3P` は 2026-06-01 作成で、最終取り込みは 2026-09-07）

## 3. 想定外だったこと: 104-02 の削除

1 回目の取り込み（job `OOVWDYPNU7`）で「削除 1」が出た。調べると次のことが分かった。

- `IN-EL-12-104-02-E-H01.pdf` は 2026-09-07 に fmp から KB バケットへ移されていた（fmp の控えは同日の日付）。chatlogs-dev では、KB バケット側の URI として 11/6〜11/7 に引用されている
- その後、誰かが KB バケットから削除していた。今回の取り込みで、その削除が検索にも反映された
- KB バケットはバージョン管理が無効で、CloudTrail（管理イベント）にも S3 の削除記録がない。**誰が・いつ・なぜ消したかは分かっていない**

意図して外したものかどうかが分からないため、itai の判断で #3 として戻した。資料一覧（[kb-metadata-catalog.tsv](./kb-metadata-catalog.tsv)）には 104-02 の行はない。
