**(1) What is Trace Data? - Technical Structure**

**Data Composition**

Trace data is categorized into several types depending on the function (some models also include Door and Group Control traces):

- **Control:** (e.g., Brake operations)
- **Management:** (e.g., Car call registration)
- **Drive:** (e.g., Motor startup/inverter status)

Each trace records external signals (e.g., SN_29), CPU-calculated data, car speed, and elevator status in **bit format**. Signals are displayed chronologically:

- **Left Side:** Oldest data
- **Right Side:** Newest data

**How Data is Recorded**

Data is updated at every calculation cycle (e.g., every 50ms). As new data enters, the oldest data is overwritten in a continuous loop. When a fault is detected (**Trigger Condition**), the recording stops and the data is preserved, preventing it from being overwritten by new information.

**What is a "Trigger"?**

The trigger acts like a "shutter" or a "save switch." It is a pre-defined fault condition that, when met, causes the system to freeze and save the current trace data for analysis.

**Reference Diagrams: Understanding Calculation Cycles**

| Trace Type | Calculation Cycle | Trigger Point Position | Purpose |
| --- | --- | --- | --- |
| **Control** | **50ms** | **Centered** | Monitors travel-related signals. The trigger is centered to show behavior **before and after** the fault. |
| **Management** | **100ms** | **At the End (Right)** | Monitors landing buttons, etc. Focuses on the status **leading up to** the fault to identify the cause. |
| **Drive** | **10ms** | **At the End (Right)** | Monitors main circuit safety checks. Like Management, it focuses on the state **immediately before** the fault. |

**⚠️ IMPORTANT: Time Synchronization Note**

Please be aware that the **Calculation Cycle (CPU processing time)** differs between Control, Management, and Drive traces.

**This means that data in the same vertical column does NOT represent the same point in time.**

*Example of data in the same column:*

- **Control (50ms cycle):** Data from **50ms before** the trigger.
- **Management (100ms cycle):** Data from **900ms before** the trigger.
- **Drive (10ms cycle):** Data from **90ms before** the trigger.

**Conclusion:** When analyzing multiple traces simultaneously, you must calculate the actual time offset based on each trace's specific calculation cycle.

トレースデータとは昇降機に不具合があった際、その不具合発生時点（トリガ点）の前後における信号の設定 値変化を確認する昇降機メニューの機能である。トレースデータを用いて不具合発生時点前後の信号の設定値変 化を見ることで、不具合原因の特定などに活かすことができる。主に稲電から不具合原因追求のためトレースデ ータの提出を要求された際に使用する。
